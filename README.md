# Money Flow Radar v2 — AGIP 스타일 독립형 장마감 대시보드

**기존 키움 + 인포스탁 프로그램과 무관한 별도 프로젝트입니다.** 기존 GitHub 저장소를 수정하지 않습니다. 이 ZIP은 새 저장소에만 업로드하세요.

## 화면 기능
- 상단 시장 요약: 분석 종목 수 / 거래대금 합계 / 상승 종목 수 / 강세 신호 / 최상위 섹터
- 왼쪽: 신규 강세 신호, 거래대금 TOP 100 (필터·정렬·CSV 저장)
- 오른쪽: 종목 클릭 시 상세 정보, 종가/거래대금/전일·5일·20일 대비 거래대금/20일선 이격도
- 섹터·테마별 거래대금 그래프, 섹터 내 거래대금순 종목 목록
- 관심종목 등록: 브라우저 로컬 저장소에만 저장, 다른 기기 동기화 안 됨
- PC 대시보드 / 스마트폰 반응형 화면
- **샘플 시세를 실제 시세로 위장하지 않음**: data/latest.json 없으면 '수집 필요' 표기


## 키움 REST API 수집기로 교체 (2026-11-06)
- 기존 `pykrx` 수집 대신 **키움 REST API** 사용. 기존 키움·인포스탁 프로젝트는 수정하지 않음.
- `au10001` 토큰 발급 → `ka10032` 코스피/코스닥 거래대금 순위 → `ka10081` 선정 종목 일봉(최소 21거래일) 순서.
- `ka10081` 응답의 거래대금 `trde_prica` 단위는 **백만원**이므로 웹 표시 억원으로 변환 시 100으로 나눔.
- 새 저장소 **Settings → Secrets and variables → Actions → New repository secret**에 `KIWOOM_APP_KEY`, `KIWOOM_APP_SECRET` 각각 등록. 인증값은 공개 코드나 채팅에 게시하지 말 것.
- GitHub Actions에서 `Run workflow` 수동 실행 후 `Collect market data (Kiwoom REST)` 로그 확인. 토큰·실거래 데이터 확인 전 정상 수집으로 간주하지 않음.
- 평일 17:30 KST 예약은 유지. 장 마감 전 수동 실행은 장중 잠정 수치가 될 수 있으므로 매매 판단에 사용 주의.
- **한계**: 일봉 21개 미만 신규 상장 종목은 제외, 인포스탁 섹터 CSV 수동 매핑 유지, API 호출 제한 및 GitHub 호스팅 IP/접근 제한 확인 필요.
- 데이터 수집 실패 시 기존 data/latest.json 보존, 화면 배포만 성공할 수 있으므로 Actions summary의 수집 경고도 확인해야 함.
- 실제 인증키 연동과 키움 데이터 응답은 아직 운영 환경에서 검증 전.

## 데이터 수집 및 운영 (아래 기존 pykrx 설명은 교체 전 이력)

- Python `pykrx`로 KOSPI/KOSDAQ 당일 거래대금 상위 100종목을 가져옵니다.
- 이전 20개 거래일 조회하여 전일, 이전 5일 및 이전 20일 평균 거래대금 대비 증가율 계산.
- 최근 20거래일 종가 이동평균은 **당일 종가 + 직전 19개 종가**로 계산.
- 장 마감 후 평일 17:30 KST (`08:30 UTC`) GitHub Actions 예약 실행.
- 공휴일에는 최근 유효 거래일 데이터를 유지. 데이터 공급 지연과 GitHub Actions 실행 지연 가능.
- 네트워크/API 실패 시 기존 latest.json을 덮어쓰지 않고 작업 실패로 표시함.
- `data/sectors.csv`는 **수동 섹터/테마 매핑**입니다. 예시 15개 종목만 있으므로 미등록 종목은 '미분류'. 모든 종목/테마 자동 분류 기능은 포함되어 있지 않습니다.
- 하나의 종목에 복수 테마를 넣으려면 `ticker,sector`에서 `005930,반도체|AI`처럼 `|`로 구분. 섹터 합계는 중복 계산될 수 있으므로 시장 전체 거래대금과 합산하면 안 됩니다.
- Lv 등급/점수는 시장 검증되지 않은 **실험용 자체 규칙**입니다. AGIP의 독점 신호 계산식과 무관합니다.

## 새 GitHub 저장소 배포
1. GitHub에서 **별도 공개 저장소** `money-flow-radar-v2`를 생성합니다. 기존 프로젝트 저장소는 건드리지 마세요.
2. ZIP을 풀어 내부 파일 전체(숨김 `.github` 포함)를 새 저장소의 최상위 폴더에 업로드합니다. `index.html`은 저장소 루트에 있어야 합니다.
3. Settings → Pages → Build and deployment → Source에서 **GitHub Actions** 선택.
4. Settings → Actions → General → Workflow permissions → **Read and write permissions** 허용. 조직 정책이나 저장소 설정상 불가능한 경우 별도 배포 구성이 필요합니다.
5. Actions → **Daily KRX collection and Pages deployment** → Run workflow를 눌러 1회 실행합니다.
6. 성공 후 Settings → Pages에 표시된 웹 주소로 접속합니다. 이후 평일 17:30 KST마다 자동 실행을 시도합니다. 예약 실행은 GitHub 서버 사정에 따라 지연되거나 건너뛰어질 수 있습니다.

> GitHub Pages는 정적 화면만 제공합니다. 데이터 수집은 GitHub Actions의 Python 스크립트가 실행합니다. 최초 실행 전 `data/latest.json`은 없으므로 웹에 '수집 필요'가 표시되는 것이 정상입니다.

## PC 로컬 실행 (Python 3.11 이상)
```bash
pip install -r requirements.txt
python scripts/collect.py
python -m http.server 8000
```
브라우저에서 `http://localhost:8000/` 열기. `index.html`을 파일로 직접 열면 브라우저의 JSON 접근 제한이 있을 수 있습니다.

## 신호 정의
- 점수(0~100): 상위 100종목 내 1위 대비 상대 거래대금 규모 40, 이전 5일 평균 대비 급증 25, 당일 수익률 20, 이전 20일 평균 대비 급증 15.
- Lv1: 점수 35 이상, 5일 평균 대비 +20% 이상, 당일 상승.
- Lv2: 점수 55 이상, 5일 평균 대비 +50% 이상, 당일 상승.
- Lv3: 점수 75 이상, 5일 평균 대비 +100% 이상, 당일 상승.
- 해당 등급은 **가설적 휴리스틱**, 투자 추천이나 백테스트 완료 신호가 아닙니다.

## 유의 사항
- `pykrx`가 공식 KRX 공개 사이트의 자료를 조회하므로 사이트 변경, 차단, 최신 시장 데이터 지연, 신규상장 주식 등으로 수집에 실패할 수 있습니다.
- 실제 장마감 KRX 데이터와 GitHub Pages 배포는 이 제작 환경에서 네트워크까지 연동한 실증 검증이 **완료되지 않았습니다**. 업로드 후 최초 Actions 실행 로그를 반드시 확인해야 합니다.
- 17:30 KST 수집은 정규장 마감 이후일 뿐 실시간 수급/체결 데이터가 아닙니다.
- CSV의 초기 섹터 분류는 예시이며 실제 투자용 데이터는 검수해야 합니다.
- API 키, 증권 계정 정보 등을 공개 GitHub 저장소에 업로드하지 마세요.
